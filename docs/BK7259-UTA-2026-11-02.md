# BK7259 官方 CLI 经 UTA 的验证记录

## 环境与问题

2026-11-02，Mac → UTA 授权接管 → SSH → Linux 测试服务器；内核
`5.15.0-173-generic`，CH340 `1a86:7523`，BK7259 Scooter EVB V2。
官方 CLI 为用户提供的 `bk_loader_linux_4.1.7.261014250.zip`，二进制 SHA256：
`7b7ab1e86144f37cadfe96c4a5bbc8cbec267cea1791583e34d591c647345401`。
没有修改官方二进制，也没有向 UTA 集成 BK 烧录协议。

原服务器已启用 Preview 7 的 4096-byte OUT 调优，但 IN 缓冲仍为端点大小 32 字节。
921600 下读取一个 4 KiB 扇区，完整响应应为 4111 字节，原路径反复只收到
128/192/224 字节。独立读取等待 5 秒仍不完整，不能仅归因于工具超时。

## 修正与只读验证

`uta-ch341-rx1` 将 IN / OUT 缓冲均设为 4096，并通过只读模块参数核验加载状态。
原来的 OUT-only 驱动不会被新状态检查误认成完整修正。

修正后，独立探测收到完整 4111 字节，去除 15 字节响应头后与官方工具读取的
4096 字节完全一致。官方 115200 与 921600 的 64 KiB 读回哈希也一致。

默认工具参数仍出现切速确认失败及读扇区超时。记录中，短响应超时后设备实际已处于
921600；另一次完整扇区响应耗时约 0.75 秒，超过默认高速读取约 0.22 秒的窗口。
这与原来的永久缺字节是两种故障，不应混用同一恢复办法。

使用下述官方配置后，连续三轮“自动握手 → 921600 读取 64 KiB → 复位”通过，
三轮 SHA256 与上述结果一致。原始日志、设备数据和测试环境路径不公开。

## 官方工具配置

复制该 CLI 随包提供的 `config/bk_loader_config_inner.yaml`，仅调整以下等待参数；
其他项保留默认值，包括响应码、CRC、板上 CRC 状态和产品 ID 检查：

```yaml
set_baudrate:
  cmd_delay_ms: 250
  switch_delay_ms: 10
  wait_response_timeout_ms: 3000
read_flash:
  retry_count: 20
  fixed_timeout_ms: 2000
  timeout_factor: 5
read_flash_mid:
  retry_count: 5
  delay_after_fail_ms: 200
  wait_response_timeout_sec: 2
```

这是完整默认配置中需要修改的部分，不是另一份烧录协议。
切速命令的设备等待字段只有一个字节，不应将 `cmd_delay_ms` 随意增大到超过 255。
`switch_delay_ms` 是主机切换波特率前的等待；设备端窗口要覆盖该等待和远程 USB 控制请求。
这些值是在本次链路上验证的配置，不保证所有网络、USB 转串口芯片都适用。

该版本 CLI 的 `--bk_loader_config_path_out` 实际支持读取所指定的外部 YAML 配置。
它是全局选项，必须放在 `read` / `download` 前面。使用存在且有效的配置路径。

```sh
bk_loader --bk_loader_config_path_out /path/to/bk-loader-uta.yaml \
  --log_path /path/to/logs --log_level 3 \
  download -p /dev/ttyUSB0 -b 921600 --reset_baudrate 115200 \
  --link_type 4 --reset_type 3 --retrycnt 1 --reboot \
  --pre_erase 1 -s 0x0 -i /path/to/BK7259/all-app.bin
```

固件和起始地址必须由对应项目确定；不能把 BK7258 镜像套用到 BK7259。
这里不使用全片擦除、eFuse 或 OTP 写入参数。
该 CLI 业务失败时也可能退出 0，因此应检查完整的成功/校验日志，不能只看进程退出码。

## 结果边界

官方 CLI 完整下载一份 4,592,672 字节的 BK7259 测试镜像成功。
耗时 162.840387 秒（约 2 分 43 秒），日志包含 `protect flash OK.` 和
`Download complete, all pass.`，随后执行复位。写入阶段约 33 KB/s；该速度只代表本次设备及链路。
额外官方首尾读取验证：首 4096 字节和末尾不足一扇区的 1056 字节均与源镜像一致。
没有另外做整片 Flash 的独立逐字节比对，也没有验证用户固件功能。

日志显示按镜像范围处理，未使用全片擦除、eFuse 或 OTP 写入选项。
本发行版不包含测试固件、其源码标识、固件哈希、原始串口日志或第三方烧录 CLI 二进制。

本地 UTA Python 回归 96 项通过，云端当前内核模块编译通过。
修正随 Preview 8 云端代理和 Mac 安装包发布；安装 App 后仍需单独更新代理和驱动。
驱动仍是本次启动期间生效，服务器重启后需重新启用。
此记录仅用于 USB 传输和烧录完整性，不表示屏幕、触摸、音频等固件功能通过验收。
