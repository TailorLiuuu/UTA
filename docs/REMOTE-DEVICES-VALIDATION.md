# 单设备授权与日志：预览验证记录

本记录对应 Preview 17（Build 30）的发布前验证。下面区分模拟测试与实机验收；安装发布不等于完成真实设备兼容性验证。

## 已完成

- 新增设备功能 20 项测试：Linux 隔离环境全部通过；Mac 通过 19 项，真实 Linux 降权验证在 Mac 上跳过并已在 Linux 补测。
- 测试包含单设备授权、不同客户端与系统 UID 隔离、撤权和过期、路由解析、多个串口拒绝猜测、日志与工具互斥、带认证的完整 stdio 往返、客户端断开清理、工具超时、输出阻塞上限、幂等回执和操作记录权限。
- 合成 PTY 测试包含 NUL、非 UTF-8 字节和换行，回传字节一致；结束后可重新打开模拟串口。没有将该结果宣称为真实设备日志零丢失。
- Linux 中验证提权代理启动的测试工具实际以非 root 用户运行。测试使用一次性源码目录、虚拟 PTY 和合成身份；不访问现有 USB。临时目录已删除，原安装 CLI 的 SHA-256 前后一致。
- Mac 新面板经过 CLI 夹具、跨帧 UTF-8、操作回执及离屏渲染测试。默认不自动选择列表首个设备、不自动打开串口；显示缓存上限 64 KiB，约每 100 ms 更新。
- 链路工作台模型/配置/CLI 测试仍通过，509 项中英文翻译检查通过；完整 App 编译通过。
- Windows 客户端现有 4 项合成测试通过。新增 Windows 桌面按钮尚未在 Windows 实机验收。
- Mac 包使用原开发者身份签名，Apple 时间戳重试成功，`codesign --verify --deep --strict` 通过。7 个原生 USB/辅助服务文件哈希保持不变。
- 接收端和 Windows 包按允许列表打包，未包含本机配置、身份凭据、固件或原始设备日志。

## 保留的限制

- 全量回归中原有 `test_inventory.test_list_cannot_open_usb_or_initialize_libusb` 未通过：本地原生夹具的拦截控制调用返回 2，而测试期望 97。本次未修改原生 USB 实现，未把此项记为通过。
- 尚未用真实开发板烧录或读取日志，没有新的实机吞吐、延迟或丢包率结论。
- 手动重新接入可能生成新的设备授权 ID，需重新选择/授权；Windows 下载模式自动接回尚未实现。
- 固件工具仍需自行满足芯片协议、环境和校验要求；任意工具拥有 SSH 账号本来的权限，UTA 操作锁不是系统沙箱。

运行新增本机测试：`bash scripts/test-ports.sh`。GUI 夹具需要可用的 macOS 图形会话；它只渲染自身内容。远端测试必须另行获得允许，不应把隔离验证脚本用于真实端口。
