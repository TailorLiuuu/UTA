# UTA 链路工作台（预览）

入口：macOS App 左侧「链路工作台」。它把电脑、服务器和两类链路画在同一张图上。

```text
Mac（编译） ── 固件文件 ──→ Linux（运行原来的烧录工具）
                                  ↑
Windows（插着开发板） ── USB 透传 ──┘
```

固件交给 Linux；Windows 提供设备。Windows 不需要再下载一份固件。
操作请求和 USB 回包是双向的；紫色箭头表示设备从哪里提供给谁，不表示 USB 数据只能单向流动。

## 编辑与保存

- 拖动节点标题移动电脑；从右侧实心端点拖到另一个节点左侧空心端点连接。
- 绿色是固件传输，紫色是 USB 提供关系。右侧详情也能通过下拉框选择目标并连线。
- 「添加节点」可以选择已有服务器配置，也可以先添加未绑定的电脑；中间节点数量可继续增加。
- 点击固件连线可「插入中继」；也可删除节点、删除连线、撤销、重做、缩放和适应画布。
- 节点需要绑定本机已有的服务器配置，设置实际系统和用途。备注可单独修改。
- 自动保存到 `~/Library/Application Support/UTA/links.json`，文件权限 0600；不会改动 USB 会话。
- 导出保留拓扑、节点备注和项目标识，移除服务器绑定、固件路径、USB 标识及接收器路径。
  分享前仍需检查自填备注是否包含隐私。导入不会执行任何命令。
- 配置损坏时保留原文件，停止自动覆盖；仍可把新方案导出到另一个文件。

## 可以实际执行的操作

1. 在源节点为本机的固件连线中，选择已编译的固件文件或文件夹。
2. 在目标节点选择对应服务器，点击「检查文件接收能力」。目标需要本次传输版本的 CLI。
   Linux/macOS 默认接收器路径 `/usr/local/bin/uta-server`；Windows 填写 `uta-server.cmd` 的完整路径。
3. 点击连线详情的「发送固件并校验」。它调用已有的 `uta send`，复用客户端身份、SSH 加密、续传和 SHA-256 校验。
4. 校验成功后显示目标文件路径与任务 ID。烧录仍使用原有工具。

文件接收能力和 USB 挂载是两种不同能力；检查文件接收不会加载 USB 模块，也不需要 sudo。
固件按所选服务器的客户端凭据和项目标识存放。不同客户端的同名文件不会被本界面合并。

## 明确的状态与边界

- 画布是可执行传输的配置入口，也是拓扑规划图，**不是实时网络发现或 USB 会话监控器**。
- 连线标识「已规划」「待确认」；不会因为画出了线就显示「已连接」。
- 当前只接入本机到已配置目标的文件发送。远端节点之间可以画出多段链路、查看顺序，
  但**尚未实现由本机一键编排远端多跳传输**；每段仍需要源节点自己的目标配置和凭据。
  不会把 Mac 的 SSH 私钥或代理授权转交给中继。
- USB 线只描述提供关系。必须在 USB 所在电脑的 UTA 中实际接入，再在目标 Linux 确认自己的设备端口。
  当前画布不会主动接管、断开、重启、刷写设备，也不自动运行编译或烧录命令。
- 删除图示不会释放真实端口；需要释放设备时使用原来的设备管理界面。
- 校验拒绝自连接、同类型循环、重复连线、模糊的多固件输入，以及已明确绑定的同一 USB 标识重复分配。
  图最多 32 个节点和 64 条连线。USB 接收目标目前必须是 Linux。
- 同一 root / OS 账号下的独立客户端身份用于防止误操作，不能代替不同系统账号的安全隔离。

## 不触碰设备的预览与验证

```sh
bash scripts/test-links.sh
bash scripts/preview-links.sh
open 'build/UTA Links Preview.app'
```

独立预览只使用虚构服务器，禁用网络操作，不扫描 USB、不启动后台控制器、不写入正式 UTA 配置。
正式 App 构建已包含工作台。独立预览本身不会替换安装版本；更新正式 App 时需保留现有配置并检查活动连接。

验证包括拓扑规则、保存/恢复、损坏文件保留、文件权限、导出脱敏，以及通过模拟 CLI 检查
目标服务器 ID、参数传递、上传结果和取消操作。实机窗口已验证节点拖动、端点连线、中继插入和撤销。
