# 烧录与日志实测 — 2026-10-27

本次优化已安装到测试 Mac 的 Build 18，对应 Preview 6。UTA 仍只负责通用 USB
透传，烧录使用云端原版 esptool；没有加入芯片专用命令、协议或自动续传。

## 稳定性修复

此前，一次独立 SSH 状态查询异常就会调用断线清理，即使 USB 数据隧道仍在工作。
这是一条可以从代码和故障注入测试确认的误断开路径；既有日志不足以认定过去
每次用户遇到的断线都由它引起。

现在状态查询至少间隔 10 秒，临时失败保留通道和最后确认的端口，并显示橙色
「状态待确认」。连续失败至少 3 次、距首次失败已过 30 秒后才释放连接。
观察到导出器／SSH 隧道退出，或云端明确报告设备断开时，仍清理连接。
查询恢复后自动清除警告。连接事件写入 `logs/connection-events.jsonl`，超过约
1 MiB 轮转，保留一份历史，记录状态变化、查询失败／恢复和进程退出码。

83 项 Python 回归、3 项 Node 适配器测试及 Swift 语言／设备列表检查通过。
短暂查询失败、持续失败、恢复、进程退出、真实远端断开、新会话重置和诊断
文件写入失败由自动化测试覆盖；不等同于已经完成实机弱网压力测试。

## 原版工具烧录

设备为 USB 串口桥连接的 ESP32-S31，固件为 RingHiDesktop 0.7.0。
先独立校验设备 Flash 与保存镜像摘要一致，再重复写入同一个 1,605,824 字节
应用镜像，仅写 `0x10000` 应用区域，不擦除配置分区。使用 esptool 5.6.0 的
`--no-stub`、DIO / 16 MB / 80 MHz 设置。

| 串口波特率 | 镜像写入时间 | 含连接、擦除、校验的总时间 | 结果 |
| --- | ---: | ---: | --- |
| 460800 | 71.6 秒 | 79.09 秒 | 写入完成、摘要校验通过 |
| 921600 | 53.5 秒 | 60.73 秒 | 写入完成、摘要校验通过 |

写入时间缩短约 25%，全流程缩短约 23%。随后单独运行 `verify-flash` 再次摘要
校验通过，并从串口确认原固件启动运行。摘要校验不是重新传输整个镜像，
不能将它的约 4.8 秒耗时当作全镜像传输速度。

两档各测一次，期间控制器从旧版本升级到 Build 18；USB helper、客户端与原生
数据传输二进制保持一致。主要可调项是外部工具的波特率，不能将这次结果说成
UTA 对所有设备统一提速 25%。更高波特率也不能消除逐命令等待应答的网络开销。
其他板卡和线缆应自行验证，不应全局强制使用 921600。

## 串口日志

在服务器独占读取同一虚拟串口，115200 / 8N1，保存原始字节和每块数据的
接收时间；按完整 `RH_STATUS` JSON 分析设备运行时间和启动编号。开头尚未
接收完整的残留行不计为解析错误。

| 指标 | 升级前采样 | Build 18 烧录后采样 |
| --- | ---: | ---: |
| 时长 | 180.03 秒 | 300.02 秒 |
| 字节数 | 215,096 | 348,567 |
| 完整状态记录 | 81 | 135 |
| 状态 JSON 解析错误 | 0 | 0 |
| 采样期间意外重启／串口断开 | 0 / 0 | 0 / 0 |
| 相邻状态的设备运行时间最大间隔 | 2.692 秒 | 2.790 秒 |
| 相邻完整状态的接收时间最大间隔 | 2.714 秒 | 2.945 秒 |

两段均未发现大于 3 秒的设备状态间隔，也没有持续增长的接收积压。
Build 18 的「接收时间变化减设备运行时间变化」相对首个样本峰值约 +0.50 秒，
结束约 -0.29 秒；这包含设备时钟漂移和发送调度，**不是准确的单程 USB 延迟**。
当前链路 20 次 ping 的往返均值 10.55 ms、最大 12.63 ms，无 ICMP 丢包；
ICMP 结果不能用来证明 USB 或串口零丢失。

固件约每 2 秒生成一条状态，完整状态约 2.5–2.6 KB，115200 / 8N1 下串口发送
本身约需 215–230 ms。完整 JSON 显示速度同时受固件输出周期、串口串行化、
USB、网络和读取工具影响，不能全部归因于 UTA。

## 证据边界与复测方法

- 这是约 1.2 KB/s 的普通日志采样，不是串口满载、长时间耐久或弱网压力测试。
- 状态没有逐字节序号；没有观察到缺口或解析错误，不能证明每个日志字节绝不丢失。
- 烧录中间的复位是测试主动触发；5 分钟日志窗口从最后一次校验后的启动开始，
  此后启动编号保持不变。
- 串口需独占读取。其他串口窗口、烧录工具改变波特率或触发复位，会污染结果。
- 精确丢失率应使用带序号、长度和校验和的连续测试数据，并在发送端保留计数；
  精确单程延迟需要同步时钟或外部测量。本轮未改写测试固件来做这些实验。
- 本轮没有重新验证默认 stub 模式的大块读取问题，也没有测试 ML307H 或其他芯片。

原始采样、时间索引和烧录日志保存在私有测试目录，未纳入 Git 或安装包。
安装后已确认 App 显示一个挂载设备和对应云端串口，测试读取进程退出，
设备保留接入状态，日志波特率恢复为 115200。
