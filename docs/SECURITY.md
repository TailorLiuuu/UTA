# UTA 会话安全边界

本文件描述 Preview 14 的会话认证加固。它不是独立安全审计认证，也不是对任意 USB
设备或多租户服务器的完整隔离保证。UTA 仍是通用 USB/IP 透传；烧录协议由原来的工具处理。

## 会话认证

SSH 继续负责加密传输、服务器指纹校验和 SSH 账号认证。反向监听只请求绑定
`127.0.0.1`，服务器应配置 `GatewayPorts no` 或 `clientspecified`。

每次接入（包括重新枚举后的重新接入）生成独立的 256 位随机密钥，绑定会话 ID、USB
busid 和云端实际 Linux UID。双方通过 HMAC-SHA256、独立随机挑战及角色标识互相认证。
旧连接的认证报文不能重放到新的挑战；导出器只接受一条成功认证的连接，随后关闭监听。
失败认证不会消耗这条连接的机会，也不会启动 USB 导出或接管设备。

密钥只通过本机子进程管道和 SSH 标准输入传递，不写入会话记录、命令参数或诊断日志。
本机中转 socket 目录为 `0700`，socket 为 `0600`。发布用原生导出器只接收已连接的
IPC 描述符，不再提供未认证的 TCP `export` 入口。

认证发生在 USB/IP 导入和 Linux 内核接管 socket 之前，增加约两次网络往返。
认证后保持原始 USB/IP 字节流，没有逐包 HMAC、烧录协议适配或速率限制。
普通路径直接交接 socket；授权路径继续使用现有辅助服务管道。

新版 Mac CLI 要求云端 `doctor` 返回 `session_auth: 1` 和 `client_identity: 1`。新版云端拒绝没有
`--auth-stdin` 的接入，不会降级为未认证模式。升级时两端需要配套；旧版 App 的新接入
也会被新版云端拒绝。已有连接无需为此强制终止，应完成使用并断开后再更新。

## 客户端归属与共用 root 的误操作防护

App 在私有目录中保存随机身份种子（独立于服务器配置和诊断记录，文件 `0600`）。每个
已保存服务器配置派生独立的 256 位凭据；同一安装/配置重启后身份稳定，另一台 Mac 或
另一个服务器配置的凭据不同。复制服务器配置文件不会复制身份；复制私有种子则会。
修改服务器备注不改变其配置 ID，因此不改变凭据。

客户端 ID 是带固定用途标识的凭据 SHA-256 摘要，服务端验证凭据与 ID 的对应关系。
只有 ID 不能冒用身份；接入记录只保存 ID，不保存凭据。管理命令通过 SSH 标准输入
传递凭据，接入时下一行才是单次数据连接认证配置；不在命令参数、App 状态或日志中暴露。
这是经 SSH 保护的持有者凭据，不是非对称签名或抵御 root 的密码学隔离。

`list`、`status`、`detach`、`resolve` 默认同时检查 Linux UID 与客户端身份，即使 UID
为 0 也不会自动绕过。无凭据时明确报错，不默认显示全部；凭据错误或跨客户端操作被拒绝。
普通管理操作也不能认领旧会话或更改其归属。两位同事的设备即使拥有相同型号和本地 busid，
仍以不同随机会话和客户端身份区分。

云端终端/远程开发会话需要明确选择自己的凭据文件（见 [客户端上下文指南](CLIENT-IDENTITY.md)）。
不要为共用 root 配置一个全局默认凭据；终端的 SSH 密钥不同并不会自动选择 UTA 客户端。
`resolve --route ID` 只在当前客户端范围内查询唯一已就绪的连接，自动重连沿用 route ID，
返回当前设备节点；未就绪或有歧义时报错，不复用旧端口。它不是持久文件句柄或自动续烧。

真正的 root 管理员可以显式使用 `list/status/detach --admin` 管理全部会话。App 不调用该
选项，受限 sudo 用户不能借此提升管理范围。没有 `client_id` 的旧记录只在管理员模式可见，
不会按共用 root 猜测归属；升级前应让旧连接完成、断开并完成清理，遗留记录需管理员明确处理。
不会通过扫描正在连接的设备来自动认领它们。

凭据丢失或被删除后无法自动恢复旧身份；不得把身份文件作为普通缓存清理。凭据导出只写新文件，
不覆盖已有文件；文件包含该客户端在对应服务器配置范围内的管理权限，请勿分享给其他同事或提交到仓库。
当前没有在线吊销服务；泄露时需清理受影响会话并停用旧身份，不能仅删除某份导出文件就宣称已吊销。
这些检查仅影响连接/查询/断开等管理操作，不增加逐 URB 工作，不改变烧录协议或带宽设置。

## 账号与节点权限

新客户端在云端声明支持 `session_lease` 时，以 `--lease-seconds 60` 接入。
云端独立进程每两秒检查该会话；只有所属客户端的 `status --session` 查询续期，
`list`、`resolve` 和管理员查询不续期。Mac 离线、休眠或无法发送清理请求时，
约 60–62 秒后释放对应虚拟端口。释放前重新核对客户端、UID、socket 和端口，
不处理已经复用给其他连接的端口；晚到的心跳不能复活过期会话。
这不向 USB 数据流插入心跳或校验，不限制传输速率。旧客户端及手动 CLI 接入默认
不启用租约；已接入的会话也不在更新时被强制转换。云端守护进程正常调度且状态目录、
sysfs 可用是到期清理的前提。尚未进行物理 USB 验收的构建不能作为实机可靠性证据。

- 以 SSH 登录账号对应的 Linux UID（sudo 场景为 sudo 设置的 `SUDO_UID`）记录所属者。
  同时验证客户端凭据和 UID；root 只有显式管理员模式才扩大管理范围。
- 云端状态目录要求 root 所有、`0700`；记录与锁文件为 `0600`。拒绝符号链接和不可信
  所有者/写权限，限制读取大小，使用独占临时文件及原子替换。旧的 root 所有、不可被
  普通用户改写的 `0644` 记录在读取时收紧为 `0600`。
- 对已枚举并确认属于该会话的串口、hidraw 和 usbfs 字符节点，核对 sysfs 主次设备号后
  将访问权限收紧为所属 UID、`0600`；不通过打开串口来修改权限。
- CLI 应安装为 root 所有、普通用户不可改写。委派 sudo 时只允许经过审查的 CLI，保留
  sudo 的环境清理，不授予 `SETENV`、任意 Python 或 shell 执行权限。

这里的隔离有明确边界：

1. 两个人共用同一个 Linux 账号（尤其 root）仍是同一权限主体。服务器备注和会话 ID
   不是操作系统隔离机制。客户端凭据防止常规 UTA 操作串线，但不能阻止 root 显式使用管理员
   模式、读取他人凭据或直接操作设备节点。root、任意 sudo 权限和同一 Mac 用户不在强隔离范围内。
2. 节点权限是在枚举后查询状态时收紧的；初始 udev 创建设备的窗口、后续 udev 规则
   改写以及此前已打开的文件描述符没有被彻底隔离。需要敌对租户隔离时，应再设计
   枚举前生效的设备策略、受限设备类别与 VM/设备访问控制，并单独验证。
3. 完整 USB 接入允许远端驱动发出设备控制请求，包括复位和写固件，不能作为“只读日志”
   权限。不要将不受信任的服务器连接到敏感 USB 设备。
4. 授权模式的原生 USB/IP 解析仍在特权辅助服务中；本轮增加认证与资源上限，没有完成
   解析进程降权或沙箱拆分。内核 USB 驱动也仍是信任边界的一部分。

## 资源上限

| 范围 | 上限 | 超限处理 |
| --- | --- | --- |
| 单次认证 | 3 秒 | 关闭该候选连接 |
| 每个导出器的并发认证 | 8 个 | 拒绝额外候选 |
| 导出器首次接入等待 | 30 秒 | 退出并清理本机 socket |
| 单个 USB 传输缓冲区 | 16 MiB（保留原上限） | 断开该会话 |
| 单个传输等时包数 | 1024（保留原上限） | 断开该会话 |
| 单会话在途申请 | 64 MiB、1024 个请求 | 在分配前拒绝并断开该会话 |
| 单个原生进程在途申请总量 | 256 MiB、4096 个请求 | 在分配前拒绝并断开超限会话 |
| 单会话尚未发完的响应 | 2048 个 | 断开该会话，释放队列 |

在途字节按传输大小、等时元数据和每请求固定开销计费，从分配前保留到 USB 完成及响应
发出/销毁后释放。这不是总 RSS 硬限制，也不是跨所有导出器进程的全局限制。
同时校验端点范围及控制传输方向/长度，拒绝异常报文。

这些是积压上限，不是每秒请求数或带宽配额。正常空闲串口不增加接收超时；CH341
优化、USB 分包和外部烧录工具保持原样。大量排队的特殊 USB 工作负载仍需兼容性验证。

## 验证

本地测试使用虚拟端点，不枚举、接管或烧写真实 USB：

```bash
cmake -S native -B build/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/native -j6
python3 -m unittest discover -s tests
python3 scripts/build-server.py
```

`tests/test_session_security.py` 覆盖双向认证、错误密钥、跨账号/设备/会话、重放、认证超时、
凭据传递、状态文件与账号权限、节点权限、请求/字节/响应队列上限、异常控制报文，以及
普通和授权管道的短包/数据完整性与断开清理。辅助服务在测试中使用模拟端点。

`tests/test_client_identity.py` 覆盖身份持久化/并发创建、同 root 客户端隔离、伪造 ID 拒绝、
默认无上下文报错、显式管理员边界、旧记录、凭据安全导出以及重连后的端口查询。

ASan/UBSan 可用独立 CMake 构建；通过 `UTA_TEST_FIXTURE` 指定其 `uta-test-fixture`。
测试通过不等于已经验证实机烧录耗时、远程 Linux 设备权限或完整多租户隔离。
